## 简化投保与 OLA

投保问卷共五步：基本信息、业务连续性、财务影响、保障条件、确认提交。默认 AI API 单业务样例 CBU-007；CBU-001 报告典型客户仍保留。基本信息仅保留企业名称及核心服务字段。独立业务标识、准入辖区等定价信息在参考档案内部保留，不因隐藏而视为无需核实。

AI API 的 OLA 是两步约定：

1. 服务标准：列明模型、接口、实际使用地区；约定有效调用在响应时限内成功的比例。默认 99%、30 秒，仅为前端演示约定。
2. 测量规则：企业调用日志与独立测试交叉核验；默认按 5 分钟窗口判定不达标，恢复须连续达标 5 分钟。有效样本不足或证据冲突转人工复核。错误密钥、企业自身配置等约定除外原因不计入承保中断。原服务或已接入且能接管业务的备用达标后，经确认回溯至恢复窗口起点截止；等待期另扣。

新保单冻结全部服务与 OLA 字段；旧已确认保单不追加条款。未确认旧样例补齐演示 OLA 时清除旧报价。用户修改模型、使用地区或 OLA 参数，会触发重新测算。既有报告未根据这些具体阈值校准分钟级调用事故率；参考价格仍是原报告条件命中与时长情景，不能声称已完成 OLA 经验校准。监测图由申报区间生成，为模拟回放，人工核对材料及责任后才可核赔；未接入真实日志分析。

仅凭部署位置不能报价。M1 还需要服务商、产品与运行故障/恢复经验，M2 还需要关键上游、适用主体/法域、已知限制及迁移准备；两者都需要业务损失口径、营业时间、OLA、备用及限额。模块显示保费目前按期望赔款占比分摊，并非分别完成模块再保/资本边际定价。

## 计算来源与可交互范围

`dist/unified-data.js` 来自交付报告的同名 JSON，含100张差异化示例保单、10套完整组合结果、39条候选事件及报告参数。每个情景由报告程序运行200,000个模拟年度。网页不再运行旧的三客户/比例分保模型。

定价模型页面可选择基准、M1频率、M2强弱、M2未获再保和首次投保年度情景，并调整资本成本率、再保费用加载和变动费用率。财务参数在同一赔款分布上重算；风险情景读取各自的预计算结果。风险暴露、日历或限额不匹配时，报价显示“待重新测算”，不会用旧报价或比例缩放冒充重跑。承保组合提供100张参考档案及分页载入。全组合备用、集中度变化只供敏感性对照，不直接作为未改投保条件的可出单价格。

这是静态研究前端：没有新增真实保单后的组合重模拟服务。复制样例仍引用原组合参考档案，不代表第101张真实保单已获得容量；核保增加了组合容量及共同依赖复核。

## 核赔对齐

- 逐业务计算参数金额，并按不可追回贡献毛利净损失封顶，再汇总应用同一事件和年度限额。贡献毛利已扣节省的变动成本；同损失补偿另扣一次，不含迁移等额外费用。
- 事故报告可增加同一事件的其他独立业务，并分别填写恢复时间与净损失；不得重复列入同一业务。
- 样例AI：400/h × 3个可赔小时 = 1,200；实际净损失560，最终赔560。
- 样例M2：2026-12-20公告，2027-01-10实际中断；首次承保2026-01-01，连续续保。核心业务1.5小时中断，赔600；AI业务4小时中断，赔1,400；合计2,000。
- 本年度发生的连续中断可以在到期后恢复，赔款仍归原责任年度，不刷新下一年度限额。首次投保前已知具体停供安排仍除外；不连续续保不追溯衔接。
- 其他业务行的“恢复”应填写实际业务恢复（包括成功切换）的较早时点；详细证据仍在材料中复核。
